# Lessons learned

The Reviewer agent adds a line here when it finds an issue that is likely to repeat. Every run reads this file first. Keep each lesson to one line, newest first. Remove lessons that no longer apply.

Format: `- YYYY-MM-DD | asset type | lesson`

- 2026-10-16 | checklist CSV | Timing offsets (go/no-go, kit ready, quiz dates) drift from 06-campaign-strategy.md. Copy each offset from 06 word for word, then compare every dated row against it before finishing.
- 2026-10-16 | channel copy, design briefs | On-image text over the word cap forces design to cut it, and copy and visuals drift. Write on-image text within the cap in 07 (count the limits box), so design renders it unchanged.
- 2026-10-16 | sales objection answers | Do not explain how a feature works beyond what the PRD states (for example, how restored attachments relate to deletion time). Stop at the PRD wording and add a [NEED PROOF: ...] tag for the gap.
- 2026-10-16 | sales talk track | Do not state customer patterns as fact ("rarely", "usually", "often") without proof. Describe the scenario ("can run to thousands of issues") or turn it into a question to the buyer.
- 2026-10-16 | checklist CSV | Quote every Task field that has commas or quotes, and make each Depends On entry match a Task name exactly. Keep Task names short and put detail in Definition of Done. Re-validate: same column count on every row.
- 2026-10-16 | in-app, LinkedIn, one-pager | Short assets drop the must-say limitations first. Write the limitations into the draft before any other copy, then cut other words to fit the length limit.
- (seed) | all | Headlines drift toward feature names. Lead with what the admin gets back, not what the feature is called.
- (seed) | email | Subject lines over 50 characters get cut off on mobile. Keep them under 50.
