# Lessons learned

The Reviewer agent adds a line here when it finds an issue that is likely to repeat. Every run reads this file first. Keep each lesson to one line, newest first. Remove lessons that no longer apply.

Format: `- YYYY-MM-DD | asset type | lesson`

- 2026-11-09 | review fixes, all assets | A recommended fix must not state a customer pattern with "often", "usually" or "rarely". Fix by describing the situation ("can mean rebuilding the week") or asking the reader. Reviewers check their own fixes for this.
- 2026-11-09 | skills, briefs, tiering | Do not repeat the same KPI or date text in every table row or in several files. Say it once and point to it. Cut sections that restate another file or explain what was left out.
- 2026-11-09 | answer keys, source references | When a section is cut, search every file for references to it ("see 05, Alternatives") and update them. Stale pointers survive trims.
- 2026-11-09 | in-app message, checklist | A word cap smaller than the Must say list cannot be met by copy alone. Flag it for a human in the copy file in the first draft, and make the checklist task quote the same word figures as the review, so the two do not drift.
- 2026-11-09 | checklist, campaign strategy | When a decision is made in a revision (a button label, a quiz date), close the checklist task and open-questions row that asked it. Stale tasks keep asking settled questions.
- 2026-11-09 | checklist | The checklist agent must read every upstream file (04, 05, 06, 10), not only 07, or [NEED PROOF] items from those files get no task.
- 2026-10-16 | sales talk track, session plan | A shortened limitation loses words like "by an agent" or "restored" and broadens the limit. Copy the Must say wording from 06-messaging.md exactly, and cut other words instead.
- 2026-10-16 | all assets | Hand-counted character and word counts come out off by one or more. Recount with a tool, or write "about N". Never state an exact count you did not verify.
- 2026-10-16 | quiz, checklist | A proposed value (such as the quiz pass mark) is written as fact while 06 and 10 treat it as open. Label it "illustrative" or "proposed, to confirm". Planning values are filled in, never left as [NEED PROOF].
- 2026-10-16 | checklist CSV | Timing offsets (go/no-go, kit ready, quiz dates) drift from 07-campaign-strategy.md. Copy each offset from 07 word for word, then compare every dated row against it before finishing.
- 2026-10-16 | channel copy, design briefs | On-image text over the word cap forces design to cut it, and copy and visuals drift. Write on-image text within the cap in 07, so design renders it unchanged.
- 2026-10-16 | sales talk track | Do not state customer patterns as fact ("rarely", "usually", "often") without proof. Describe the scenario ("can run to thousands of issues") or turn it into a question to the buyer.
- 2026-10-16 | checklist CSV | Quote every Task field that has commas or quotes, and make each Depends On entry match a Task name exactly. Keep Task names short and put detail in Definition of Done. Re-validate: same column count on every row.
- 2026-10-16 | in-app, LinkedIn, one-pager | Short assets drop the must-say limitations first. Write the limitations into the draft before any other copy, then cut other words to fit the length limit.
- (seed) | all | Headlines drift toward feature names. Lead with what the customer gets, not what the feature is called.
- (seed) | email | Subject lines over 50 characters get cut off on mobile. Keep them under 50.
